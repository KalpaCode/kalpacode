# PRD：个人技术博客与 AI 智能体

| 项目属性 | 内容 |
|---|---|
| 产品名称 | 个人博客 + AI 导览智能体 |
| 产品阶段 | 0 → 1（全新搭建） |
| 目标用户 | 技术访客（读者）、博主本人（管理者） |
| 文档版本 | v1.0 |
| 更新日期 | 2026-08-15 |

---

## 1. 需求背景

博主长期在 GitHub、掘金等平台分散发布技术内容，缺少一个可完全掌控的个人阵地：平台样式无法定制、内容无法沉淀为个人品牌、读者看完文章即离开没有二次触达 [PM 判断]。同时，单纯的文章列表型博客对陌生访客不够友好——访客带着具体问题来（"博主写过 Redis 相关的实践吗"），却只能靠肉眼翻列表或站内搜索碰运气。

本产品通过两个核心构件解决上述问题：

- **博客前台**：Markdown 驱动的静态技术博客，承载文章、分类、标签、搜索，作为个人技术名片
- **AI 导览智能体**：基于博客文章构建知识库的对话式助手，访客用自然语言提问即可获得基于文章内容的回答与推荐，替代传统的翻列表/搜关键词体验

## 2. 需求目标

| 目标 | 衡量方式 |
|---|---|
| 建立可长期持有的个人技术阵地 | 域名 + 服务器 + HTTPS 全链路自主可控，年成本控制在 500 元内 |
| 访客问题在站内闭环 | 访客提问后，智能体能基于文章给出回答并附相关文章链接 |
| 写作流程低摩擦 | 一篇新 Markdown 文章从提交到发布上线 + 知识库更新，无需手动操作 |
| 访问性能达标 | 首页静态资源加载 ≤ 2s，智能体首字响应 ≤ 3s（3M 带宽条件下） |

## 3. 用户角色与核心场景

### 角色

| 角色 | 说明 | 使用频率 | 核心诉求 |
|---|---|---|---|
| 访客 | 通过搜索/分享链接进入博客的技术人员 | 单次或低频回访 | 快速找到答案、判断博主技术水平、低成本深入阅读 |
| 博主 | 唯一管理员，负责写作与运维 | 高频 | 发布顺畅、成本可控、了解读者在问什么 |

### 核心场景（按优先级）

1. **访客带着问题来**：从搜索引擎进入某篇文章，读完后产生关联疑问，点击右下角聊天按钮提问，智能体基于其他文章回答并推荐延伸阅读
2. **访客初次到访**：进入首页看到博主简介与精选文章，对博主领域产生整体认知
3. **博主发布文章**：本地写好 Markdown 推送到仓库，自动构建部署，新内容自动进入智能体知识库
4. **博主复盘**：查看访问统计与高频提问列表，据此决定下一篇写什么

## 4. 功能需求详情

### 4.1 博客前台

#### 页面布局

```
┌─────────────────────────────────────────────┐
│ Logo   首页  归档  分类  标签  关于  [🌙/☀️] │  ← 毛玻璃导航栏 + 暗色切换
├─────────────────────────────────────────────┤
│                                             │
│          博主名字 / 一句话定位               │  ← Hero 区
│          [关于我]  [和 AI 助手聊聊 →]        │
│                                             │
├─────────────────────────────────────────────┤
│ [全部] [后端] [前端] [运维] [AI]   🔍搜索    │  ← 分类筛选 + 搜索
├─────────────────────────────────────────────┤
│ ┌─────────┐  ┌─────────┐  ┌─────────┐      │
│ │ 封面图   │  │ 封面图   │  │ 封面图   │      │  ← 文章卡片网格
│ │ 标题     │  │ 标题     │  │ 标题     │      │     (封面/标签/日期/阅读时间)
│ │ #标签 时间│  │ #标签 时间│  │ #标签 时间│      │
│ └─────────┘  └─────────┘  └─────────┘      │
├─────────────────────────────────────────────┤
│ © 2026 博主名 · RSS · GitHub                 │
└─────────────────────────────────────────────┘
```

#### 业务逻辑

- **导航栏**：固定顶部，滚动时呈现毛玻璃半透明效果；右侧提供暗色/亮色模式切换，切换结果写入 localStorage，下次访问自动恢复；移动端折叠为汉堡菜单
- **Hero 区**：展示博主名字、一句话技术定位、两个入口按钮——"关于我"跳转关于页，"和 AI 助手聊聊"点击后直接唤起右下角聊天窗并聚焦输入框
- **文章卡片**：每张卡片包含封面图（无封面时显示分类色块占位）、标题、分类标签、发布日期、预计阅读时间（按 400 字/分钟估算）；点击进入文章详情页
- **分类筛选**：点击分类 chip 过滤下方卡片网格，筛选结果实时刷新不跳页；当前选中分类高亮
- **搜索**：输入关键词后展示标题/摘要/标签命中的文章列表，支持拼音首字母匹配 [假设——待确认]，无结果时展示空状态提示并引导访客向 AI 助手提问

#### 字段规则

| 字段 | 类型 | 必填 | 约束 | 默认 |
|---|---|---|---|---|
| 文章标题 | 文本 | 是 | 2-60 字 | 无 |
| 分类 | 枚举 | 是 | 后端/前端/运维/AI | 无 |
| 标签 | 文本数组 | 否 | 0-5 个，每个 ≤10 字 | 空 |
| 封面图 | 图片 | 否 | ≤2MB，16:9 推荐 | 分类色块 |
| 摘要 | 文本 | 否 | ≤120 字 | 自动截取正文前 120 字 |

### 4.2 文章详情页

#### 页面布局

```
┌─────────────────────────────────────────────┐
│  ← 返回    文章标题                          │
│  分类 · 标签 · 日期 · 阅读时间                │
├───────────┬─────────────────┬───────────────┤
│           │                 │ 目录 (TOC)     │
│  正文区域  │   正文区域       │ - 一级标题     │
│  (含代码块)│                 │ - 二级标题     │
│           │                 │ 当前位置高亮   │
│           │                 │               │
├───────────┴─────────────────┴───────────────┤
│  上一篇 / 下一篇    [♥ 点赞]  [评论区]        │
└─────────────────────────────────────────────┘  ← 右下角：AI 聊天悬浮球
```

#### 业务逻辑

- **代码高亮**：代码块按语言自动着色（VS Code 风格配色），右上角提供一键复制按钮，复制成功后按钮文字变为"已复制"并保持 2 秒
- **目录导航**：桌面端固定于正文右侧，滚动时高亮当前阅读位置对应标题，点击平滑滚动到对应章节；移动端折叠为顶部可展开按钮
- **图片处理**：正文图片懒加载，点击放大查看（Lightbox 效果），图片加载失败时显示占位提示
- **上下篇导航**：按发布时间排列，展示相邻两篇文章的标题，无相邻文章时对应位置不渲染
- **评论区**：接入 Giscus（基于 GitHub Discussions），访客通过 GitHub 账号授权后评论，评论区无评论时显示引导文案

### 4.3 AI 导览智能体（核心模块）

#### 交互界面

```
     悬浮球状态                  展开对话状态
                        ┌─────────────────────┐
                        │ 🤖 博主AI助手  — × │
                        ├─────────────────────┤
   ┌──────┐             │ 欢迎语：我是博主的    │
   │  💬  │             │ AI助手，可问我站内    │
   └──────┘             │ 任何技术内容         │
                        ├─────────────────────┤
                        │ [用户] Docker 网络模式│
                        │ [AI] 博主在《Docker   │
                        │  网络实践》一文中...   │
                        │  📄 相关文章：链接×2  │
                        ├─────────────────────┤
                        │ [输入框...      发送] │
                        └─────────────────────┘
```

#### 业务逻辑

- **入口与唤起**：右下角悬浮球常驻所有页面；首次点击展开时展示欢迎语与 3 个建议问题（取自高频问题统计，冷启动时为博主预设）；点击 Hero 区"和 AI 助手聊聊"按钮同样唤起
- **对话流程**：访客输入问题 → 前端将问题与当前会话最近 5 轮上下文发送至 `/api/chat` → 后端检索知识库取回最相关的文章片段 → 组装 Prompt 调用 LLM → 以流式（SSE）逐字返回；回答完成后在消息下方附加"相关文章"卡片（最多 2 篇，含标题与链接）
- **多轮上下文**：会话内保留最近 5 轮问答，访客可以追问（"那 bridge 模式呢"）；上下文超出 5 轮后丢弃最早记录
- **回答生成规则**：回答必须基于检索到的文章内容，并在句末以上标形式标注来源文章；知识库中没有相关内容时，回复"站内文章暂时没有覆盖这个问题"，同时记录该问题到"未解决问题"列表，并附博主 GitHub/联系方式引导
- **会话管理**：会话 ID 存于 localStorage，刷新页面后保留历史消息（最多 20 条）；点击标题栏"清空"可重置会话
- **异常降级**：LLM API 超时（>15 秒）或报错时，聊天窗展示"AI 助手暂时休息中"，同时返回知识库检索到的原文片段作为降级答案；连续 3 次失败后 10 分钟内直接返回降级答案不再调用 LLM

#### 状态流转

| 当前状态 | 允许操作 | 下一状态 | 触发条件 |
|---|---|---|---|
| 悬浮球（收起） | 点击 | 对话展开 | 访客点击悬浮球或 Hero 入口按钮 |
| 对话展开 | 输入并发送 | 等待回答（发送按钮变 loading） | 访客点击发送或按回车 |
| 等待回答 | 无（输入框锁定） | 流式输出 | 服务端 SSE 返回首字 |
| 流式输出 | 无（输入框锁定） | 待输入 | 流式结束，输入框解锁 |
| 流式输出/待输入 | 关闭 | 悬浮球（收起） | 访客点击 × 或页面跳转 |

#### 频控与成本控制

| 规则 | 数值 |
|---|---|
| 单访客提问频率 | ≤ 10 次/分钟，超限提示"休息一下再问" |
| 单次回答 token 上限 | 800 token |
| 单日全局调用上限 | 200 次，达到后当日仅返回降级答案 |
| 相同问题缓存 | 知识库版本不变时，相同问题直接返回缓存答案 |

### 4.4 内容管理与知识库同步（博主侧）

#### 业务逻辑

- **文章发布流程**：博主在本地以 Markdown 编写文章（含 frontmatter 元信息）→ 推送到 GitHub 仓库 → CI 自动构建静态站点 → 自动部署到服务器；整个流程博主唯一的动作是 git push
- **知识库同步**：部署流程中检测到文章内容变更时，自动对新文章执行分块（按二级标题切分，单块 ≤500 字）→ 生成 Embedding → 写入向量数据库；文章删除时同步移除对应向量
- **未解决问题查看**：博主侧提供一个简单页面（或本地脚本输出），按时间倒序展示智能体无法回答的问题，作为选题参考

#### 文章 frontmatter 规范

```yaml
---
title: 文章标题
date: 2026-08-15
category: 后端        # 枚举：后端/前端/运维/AI
tags: [Docker, 网络]   # 0-5 个
cover: /images/xx.jpg  # 可选
summary: 一句话摘要    # 可选，缺省自动截取
draft: false           # true 时不发布
---
```

### 4.5 数据统计

#### 业务逻辑

- **访问统计**：接入百度统计或 Google Analytics，博主可查看 PV/UV、访客来源、热门文章排行
- **智能体统计**：后端记录每次对话的提问内容、是否命中知识库、回答耗时；按周聚合输出高频问题 Top 10 与未解决问题列表；统计数据仅博主可见

## 5. AI 智能体质量要求

| 维度 | 要求 | 评估方式 |
|---|---|---|
| 检索相关性 | 知识库中存在相关文章时，Top 3 检索片段应包含正确来源，目标命中率 ≥ 80% | 博主用 30 个预设问题集测试 |
| 回答忠实度 | 回答内容不超出检索片段范围，不编造博主未写过的技术细节 | 抽样人工核对 |
| 引用准确 | 附带的"相关文章"链接指向确实存在的文章页 | 自动化校验链接 200 状态 |
| 降级可靠 | LLM 不可用时访客仍能获得知识库原文片段，服务不中断 | 手动断开 API Key 测试 |
| 响应速度 | 首字响应 ≤ 3s（排除网络抖动），完整回答 ≤ 15s | 后端记录 P50/P95 耗时 |

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 博客页面为纯静态资源，首页首屏 ≤ 2s；智能体为页面内唯一动态组件 |
| 成本 | 服务器 99 元/年（阿里云 ECS 经济型 e 2核2G + 2G Swap），LLM API 月费 ≤ 30 元（通过频控与缓存约束） |
| 安全 | 全站 HTTPS；API 接口做频控防刷；API Key 等敏感配置不进入前端代码与 Git 仓库 |
| 合规 | 大陆服务器完成 ICP 备案；LLM 调用遵守服务商内容安全规范 |
| 可用性 | 后端进程崩溃自动重启（进程守护）；LLM 故障时降级为知识库原文返回 |
| 兼容 | 主流浏览器（Chrome/Edge/Safari/Firefox）近两年版本；移动端 375px 宽度起正常显示 |
