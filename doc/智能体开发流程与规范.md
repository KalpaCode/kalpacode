**RAG 管道流程规范：**

```
文档加载 → 文本清理 → 分块 → Embedding → 存入 ChromaDB
                                              ↓
用户提问 → Query Embedding → 向量检索 → 分数过滤 → 上下文组装 → LLM 生成 → 流式输出
```

**分块规范：**

| 参数 | 值 | 说明 |
|---|---|---|
| chunk_size | 800 token | 单块大小，平衡检索精度与上下文完整性 |
| chunk_overlap | 150 token | 块间重叠，避免语义截断 |
| separators | ["\n\n", "\n", "。", "！", "？", " "] | 分隔符优先级 |
| 代码块处理 | 不拆分 | 代码块保持在同一 chunk 内 |

**检索规范：**

| 参数 | 值 | 说明 |
|---|---|---|
| 检索方式 | similarity_search_with_score | 带分数的相似度检索 |
| top_k | 5 | 检索 5 个最相关分块 |
| score_threshold | 0.5 | 低于此分数的结果过滤掉 |
| 无结果回退 | 返回固定话术 | "博客中暂无相关内容" |

**请求/响应格式规范：**

```json
// POST /api/chat 请求
{
  "query": "什么是 RAG？",
  "conversation_id": "conv_abc123",
  "history": [
    {"question": "上一轮问题", "answer": "上一轮回答"}
  ]
}

// POST /api/chat 响应（SSE 流）
data: {"content": "RAG 是指", "done": false}
data: {"content": "检索增强生成", "done": false}

```

**对话历史规范：**

| 参数 | 值 | 说明 |
|---|---|---|

| conversation_id | UUID | 客户端首次请求生成，后续传入 |

**频率限制规范：**

| 单 IP 每天 | 200 次 | 控制成本 |

## 3. 编码规范

### 3.1 Python 规范

| 规范 | 要求 |
|---|---|
| Python 版本 | 3.11+ |
| 代码风格 | PEP 8，使用 black + ruff 格式化 |
| 类型注解 | 所有函数必须添加参数和返回值类型注解 |
| 异步 | API 路由使用 async/await，LLM 调用使用 astream |
| 配置 | 所有敏感信息通过 .env 环境变量注入，不硬编码 |
| 日志 | 使用 logging 模块，不使用 print |

**类型注解示例：**

```python
from typing import AsyncGenerator

async def chat(
    query: str,
    history: list[dict[str, str]],
    conversation_id: str
) -> AsyncGenerator[str, None]:
    """RAG 对话，流式返回回答"""
    ...
```

### 3.2 命名规范

| 类型 | 规范 | 示例 |
|---|---|---|
| 文件名 | snake_case | `chat.py`, `index_docs.py` |
| 函数名 | snake_case | `similarity_search`, `build_prompt` |
| 类名 | PascalCase | `ChatRequest`, `RAGEngine` |
| 常量 | UPPER_SNAKE | `CHUNK_SIZE`, `TOP_K` |
| 环境变量 | UPPER_SNAKE | `DEEPSEEK_API_KEY`, `DASHSCOPE_API_KEY` |

### 3.3 错误处理规范

```python
# 自定义异常层级
class AgentError(Exception):
    """智能体基础异常"""

class EmbeddingError(AgentError):
    """Embedding 生成失败"""

class RetrievalError(AgentError):
    """检索失败"""

class LLMError(AgentError):
    """LLM 调用失败"""

# API 统一错误响应
{
  "error": "retrieval_failed",
  "message": "知识库检索失败，请稍后重试",
  "status": 500
}
```

### 3.4 日志规范


## 4. System Prompt 规范

```
你是 kalpacode 博客的 AI 导览助手。

【角色定位】
你帮助访客理解博客中的技术内容，回答与博客文章相关的问题。

【回答规则】
1. 仅基于检索到的博客内容回答，不编造信息
2. 回答末尾附上引用的文章链接
3. 如果检索内容与问题不相关，回答"博客中暂无相关内容，您可以尝试换个关键词提问"
4. 技术术语保持准确性，代码示例保持原样
5. 回答简洁，直接给出答案，不要过度展开

【格式要求】
- 代码使用 markdown 代码块
- 文章链接格式：[文章标题](/posts/slug)
- 不使用 emoji
```

## 5. 文档元数据规范

每篇博客 Markdown 文件的 frontmatter 规范：

```yaml
---
title: "文章标题"           # 必填
slug: "article-slug"        # 必填，URL 路径
date: "2026-08-15"          # 必填，发布日期
tags: ["RAG", "LangChain"]  # 必填，标签数组
category: "AI"              # 必填，分类
summary: "一句话摘要"        # 必填，用于检索和展示
draft: false                # 可选，true 时不索引
---
```

索引脚本读取 frontmatter 作为 ChromaDB 文档元数据，支持按标签、分类过滤检索。

## 7. 安全规范

| 项目 | 措施 |
|---|---|
| API Key | 存储在 .env 文件，不提交 Git，服务器用环境变量注入 |
| CORS | 仅允许博客域名访问 /api/* |
| 输入校验 | Pydantic Schema 校验所有请求，限制 query 最大长度 500 字符 |
| 频率限制 | 单 IP 10 次/分钟，200 次/天 |
| 日志脱敏 | 日志中不记录完整请求内容，仅记录 query 长度和 conversation_id |
| HTTPS | 全站 Let's Encrypt 证书，API 不走 HTTP |
| 依赖安全 | 定期 `pip audit` 检查依赖漏洞 |

**CORS 配置示例：**

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://kalpacode.com", "http://localhost:4321"],
    allow_methods=["GET", "POST"],
    allow_headers=["*"],
)
```

## 8. 成本控制规范

| 措施 | 说明 |
|---|---|
| 频率限制 | 单 IP 200 次/天，防止恶意调用 |
| Embedding 缓存 | 已索引文档不重复生成 Embedding |
| 对话历史压缩 | 超过 5 轮时只保留摘要，减少 token 消耗 |
| 模型选择 | DeepSeek V4 Flash（输入 1 元/百万 token，缓存命中 0.02 元），不用 V4 Pro（贵 3 倍） |
| 上下文缓存 | DeepSeek 支持上下文缓存，重复 prompt 命中缓存价仅 0.02 元/百万 token |
| 监控告警 | 日费用超 2 元时邮件通知 |

**月成本预估：**

| 项目 | 用量 | 单价 | 月费 |
|---|---|---|---|
| DeepSeek V4 Flash 对话 | ~3000 次 | 输入 1 元/百万 token（缓存命中 0.02 元），输出 2 元/百万 token | ~8-12 元 |
| 通义千问 text-embedding-v2 | ~50 篇文档（一次性） | 0.07 元/千 token | ~1-2 元 |
| **合计** | | | **~9-14 元/月** |
